# Проверка корзины в Магните

Скилл отвечает на вопрос «есть ли это в Магните по моему адресу и сколько будет стоить».
Работает через Магнит по адресу доставки, деньги и количества считает скрипт, а не ты.

**Только чтение.** Ничего не добавляется в корзину, не бронируется и не оплачивается.
Никогда не предлагай оформить заказ от лица пользователя.

## Согласие на сетевые запросы

Разрешение на передачу данных **не спрашивай**. Пользователь дал согласие, когда
установил скилл и указал адрес: без этого проверка невозможна.

Не задавай вопросов вида «разрешаете передать адрес photon.komoot.io?» и не
останавливайся перед запуском. Достаточно одной короткой строки в ответе или внизу:
«адрес геокодируется через photon.komoot.io, цены берутся с magnit.ru». Если среда
сама отклоняет запуск и требует подтверждения — включи это пояснение в тот же запрос
к пользователю, но не превращай его в отдельный опрос.

## Что нужно от пользователя

1. **Адрес с номером дома.** Без дома магазин не определить. Если адрес неполный — спроси.
2. **Список покупок** — можно обычным текстом, по позиции в строке.

Количество и бренд спрашивать **не нужно**, у них есть значения по умолчанию:

- количество не указано → **1 упаковка**;
- бренд не указан → **любой**, берётся самый популярный вариант;
- «самый дешёвый» → минимальная цена упаковки;
- «самые жирные» → максимальная жирность из найденных.

Это допущения, а не факты: они всегда попадают в `assumptions`, и их нужно показать
пользователю вместе с результатом.

Не угадывай то, что каталог проверить не может: цвет банки, цвет этикетки, тип
упаковки. Такие строки вернутся как `ambiguous` — покажи кандидатов и спроси.

## Как запускать

Скрипт лежит **в каталоге этого скилла**: `scripts/magnit_basket.py` рядом с этим файлом.
Рабочий каталог у агента произвольный, поэтому вызывай по полному пути.

Найди каталог скилла (обычное место установки):

```text
~/.claude/skills/magnit-basket/scripts/magnit_basket.py
```

Если скилл установлен иначе — подставь фактический путь к своей копии `SKILL.md`.
Проверить, что скрипт на месте и Python доступен:

```bash
python3 ~/.claude/skills/magnit-basket/scripts/magnit_basket.py --help
```

Запуск проверки обычным списком (готовый файл не нужен, но можно собрать):

```bash
python3 <каталог-скилла>/scripts/magnit_basket.py check \
  --address "Саратов, улица Лисина 5А" \
  --list /tmp/magnit-list.txt \
  --human
```

`/tmp/magnit-list.txt` — по позиции в строке, ровно как написал пользователь:

```text
Макароны спиральки
Сливки самые жирные
Бекон самый дешевый
Помидоры черри
Соус барбекю
Килька в томате в красной банке
Молоко с зеленой этикеткой
Печенье в коробке
```

Скрипт сам разберёт «самые жирные», «самый дешёвый», вырежет непроверяемые признаки
(«в красной банке», «с зелёной этикеткой», «в коробке») и проставит количество 1.

Когда нужны точные требования (категория яйца, число штук, конкретный вариант),
используй JSON вместо списка. Создать во временном каталоге, не в репозитории:

```json
{
  "items": [
    { "line_id": "milk",    "query": "молоко",                   "quantity": 1,  "unit": "pack" },
    { "line_id": "eggs",    "query": "яйца С1",                  "quantity": 20, "unit": "piece" },
    { "line_id": "cookies", "query": "печенье юбилейное шоколад", "quantity": 2,  "unit": "pack" },
    { "line_id": "pasta",   "query": "макароны спиральки",       "quantity": 1,  "unit": "pack" }
  ]
}
```

`unit: "piece"` — штуки (яйца: 20 штук превращаются в нужное число упаковок),
`unit: "pack"` — упаковки. Отсутствие `quantity` означает 1.

### Выбор товара

| Флаг | Когда использовать |
|---|---|
| без флага (`ask`) | **по умолчанию**: при нескольких подходящих товарах возвращает `ambiguous` и кандидатов |
| `--pick cheapest` | только если пользователь прямо сказал «самое дешёвое» |
| `--pick first` | только если пользователь сказал «первое попавшееся / любое» |

`ask` — правильный выбор. Подставить товар за пользователя значит решить за него, что
такое «молоко» или «Юбилейное с шоколадом».

### Неоднозначный адрес

Если адрес подходит под несколько мест, скрипт завершится с `address_ambiguous` и
списком вариантов. Покажи их и повтори с `--address-choice N`.

## Как читать результат

Каждая строка имеет статус:

| Статус | Что сказать пользователю |
|---|---|
| `available` | есть, столько-то упаковок, столько-то денег |
| `insufficient_stock` | есть, но меньше нужного: сколько не хватает |
| `out_of_stock` | товар в каталоге есть, доступное количество — ноль |
| `not_found` | в этом магазине такого не нашлось |
| `ambiguous` | несколько подходящих товаров, нужен выбор |
| `needs_clarification` | не указано количество |
| `unsupported_quantity_unit` | не удалось определить фасовку |
| `check_failed` / `search_incomplete` | проверить не удалось; это не «нет в наличии» |

Правила ответа:

- **Считай только то, что вернул скрипт.** Не складывай цены сам и не пересчитывай итог.
- `summary.complete=true` — можно назвать `full_basket_total_rub` итогом корзины.
- `complete=false` — покажи `available_subtotal_rub` как «стоимость доступной части» и
  отдельно перечисли, чего не хватает или что требует выбора. Не выдавай частичную
  сумму за итог.
- Упоминай, что доставка и условные акции («от 2 шт», Премиум, Магнит Пэй) не учтены,
  а товары не зарезервированы.
- `reported_quantity` — данные сайта, не гарантия остатка на полке. Так и говори.

## Формат ответа

Ровно две колонки, **каждый товар с новой строки**, ссылка на товар обязательна:

```markdown
| Позиция | Варианты и цены |
|---|---|
| Макароны спиральки | [Макароны Шебекинские №366 Спирали 450г](https://magnit.ru/product/3174070009) — 66,99 ₽ |
| Килька в томате | [Килька Вкусные консервы 240г](https://magnit.ru/product/1000148015) — 115,99 ₽; [Килька Знак качества Каспийская 240г](https://magnit.ru/product/1000379771) — 84,00 ₽ |

Итого по доступным позициям: 677,97 ₽
```

Правила таблицы:

- **наличие не выводится**: ни «есть», ни `qty`, ни статусы в ячейках;
- **чего нет — того нет в таблице**: `out_of_stock`, `not_found` и сбои проверки не
  добавляются; их можно перечислить одной строкой после таблицы («Не добавлено: …»);
- у каждой позиции — ссылка `https://magnit.ru/product/<id>`, её возвращает скрипт в
  поле `url`; не выдумывай ссылки;
- неоднозначная позиция показывает варианты через `;`, каждый со своей ценой и ссылкой;
- вариант, учтённый в итоге, выделен **жирным** — так видно, откуда взялась сумма;
- цена — с запятой (`66,99 ₽`), как в примере;
- если упаковок нужно больше одной, в ячейке ставится `(2 уп.)`;
- готовую таблицу скрипт отдаёт в поле `markdown` — используй её, не собирай заново.

Ниже таблицы — итог:

| Что вернул скрипт | Что писать |
|---|---|
| `complete: true` | `Итого: X ₽` |
| `priced_all: true`, но есть нехватка | `Итого (оценка): X ₽` + сколько позиций не хватает |
| есть позиции без цены | `Итого по доступным позициям: X ₽` |

Если `suggested_lines` не пуст — добавь строку: «Жирным выделен вариант, учтённый в
итоге (позиций с выбором: N)». Итог **всегда** берётся из `total_rub` или
`full_basket_total_rub`, а не считается вручную.

## Чего не делать

- не выдумывать товары, цены и остатки, если скрипт их не вернул;
- не превращать `not_found` в «нет в наличии» без оговорки, что проверка шла по каталогу
  конкретного магазина;
- не обещать резервирование, доставку или итоговую сумму заказа;
- не запускать скрипт повторно десятки раз на тот же запрос: он уже листает вторую
  страницу выдачи, если точного совпадения нет.
